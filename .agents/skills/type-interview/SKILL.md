# Type interview

Paths below are repository-relative. Read the relevant capability parent, user
requirement and existing contracts before asking questions. Present a small model
of the meaningful variants, identities, absence/failure cases and ownership.

Separate actual ambiguity from choices already answered by the user or repository.
Ask only about material, costly-to-reverse uncertainty. Continue independent work;
do not demand a second approval for previously authorized decisions. When an answer
is essential, wait for it before implementing that dependent choice.

Write the resolved contract in its single owning location and derive boundary
types where appropriate. If implementation reveals a missing product decision,
surface it rather than weakening the model invisibly.
