# Applications

Kordex should support applications whose meaning and rules evolve: software
understanding, agent collaboration, maintainable app models, research/learning
and game semantics. These are application directions, not five shipped products.

- **D1 (P1):** exercise meaningfully different scenarios before calling a mechanism
  generic. Domain-specific state transitions remain with their domain owner.
- **D2 (P2/P3):** a declarative description needs an interpreter/validator before
  it can be claimed executable. Game descriptions alone do not implement physics.
- **D3 (P4):** generated applications declare model/code/schema authority and
  compatibility responsibilities; uncontrolled bidirectional rewriting is not sync.
- **D4 (P2/G4):** distinguish the existence of learning material from demonstrated
  understanding, and a predicted impact from a measured one.
